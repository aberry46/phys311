Porting the physics engine from Python to JavaScript honestly showed how important it is to be in a more modular state. Since we had previously separated the bodies, forces, integrators, and collision handling, much of the remaining physics translated seamlessly. I will say however that moving everything into a browser made it clearer how much the original design relied on Python's straightforward loops. Having to manage real-time rendering and fixed timesteps (along with user controls) introduced a significant level of challenges that I previous did not face with Python.

If I were start over, I would focus more on separating the physics engine from the simulation interface right from the beginning. I would also implement built-in conservation checks and provide myself with more debugging tools that would be directly coded into the engine. Overall however, I think the biggest takeaway was that the design process is more about what you are doing than what you plan to do!
